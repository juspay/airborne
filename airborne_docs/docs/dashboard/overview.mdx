The Airborne dashboard is the web console for managing over-the-air updates. From here you register the files your app downloads, bundle them into packages, ship them as targeted releases, and watch each rollout's traffic, downloads, and errors in real time — all without an app store review.

<Screenshot name="app-overview" caption="The application overview is your starting point: recent releases, deploy stats, and quick access to every feature." />

## The Organisation and Application model

Everything in Airborne lives inside two levels of hierarchy:

- An **Organisation** is the top-level workspace for a team or company. It owns applications and a roster of users.
- An **Application** lives inside an organisation and is the unit you actually ship to — for example one mobile app per platform. Files, packages, releases, dimensions, cohorts, remote configs, views, and tokens are all scoped to a single application.

You always have a **scope**: All, one organisation, one group, or one application. The **Scope** control in the header shows it in full, and it is also in the page's address, so a link or a refresh keeps it.

<Screenshot name="org-overview" caption="The organisation overview lists every application in the org and is where you create new ones." />

## Navigating the dashboard

The **header** (across the top) stays visible everywhere and contains:

- The **Scope** control on the left, one control for where you are: `All`, then an organisation, a group, an application. Open it to search or pick; each row says what it is. It also has **Create** or **Request an organisation**. On a phone it takes a row of its own.
- A global **`+ Create`** menu — a shortcut to `Create File`, `Create Package`, or `New Release` for the current app.
- The **theme toggle** (light/dark) and a **sign-out** menu.

The **left sidebar** follows the scope, in sections named for what their links belong to:

- **Control Center**, always: `Overview`, `Deployments` and `Approvals`. All three show only what is in scope.
- **Organisation · name**, whenever an organisation, group or application is in scope: the organisation's `Applications` and `Users`.
- **Application · name**, only when an application is in scope: `Files`, `Packages`, `Releases`, `Views`, `Dimensions`, `App users`, `Tokens`, `Remote Configs`, and `Cohorts`.

At application scope `Overview` is the application's own page (its status, serving policy and approvals); there is no separate Status or Summary entry. The application's older summary page is the **Classic app page** link at the foot of that page. Choosing an application in the Scope control opens that page. **Create** is always in the header; with no application in scope it first asks **Which app?**.

Changing the scope keeps the kind of page where it can: from Deployments you stay on Deployments, from an application's Files page you land on the other application's Files page.

## Running the dashboard locally

`npm run dev` in `airborne_dashboard` serves the dashboard and proxies the API through Next.js rewrites. The rewrites exist only outside production. A production build defines none, so whatever serves it has to route `/api` and the other server paths itself.

| Variable | Default | What it points at |
| --- | --- | --- |
| `BACKEND_URL` | `http://localhost:8081` | The Airborne server (`/api`, `/release`, `/build`). |
| `S3_URL` | `http://localhost:4566/hyper-ota-bucket` | The bucket that serves `/assets` and `/builds` (LocalStack by default). |
| `ANALYTICS_BACKEND_URL` | `http://localhost:6400` | The [analytics server](/docs/server/configuration#analytics-server), for the `/analytics` routes. The default is a local analytics server; without one the analytics views show connection errors instead of data. Point it elsewhere to read a shared one. |

`npm run check` runs the type check, lint, the Prettier check and `npm run test:helpers`, the plain-node checks for the Control Center helpers.
